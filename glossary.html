Glossary

Terms

SIP

Session Initiation Protocol. Application signaling that creates, modifies, and ends sessions.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

SDP

Session Description Protocol. The text format that describes media streams for offer/answer.

Sources and go deeper

  • RFC 8866 — last checked 2026-10

Offer/answer

The rule set that pairs one SDP offer with one SDP answer. The answer mirrors the offer’s m-line count and order.

Sources and go deeper

  • RFC 3264 — last checked 2026-10

RTP

Real-time Transport Protocol. Carries media samples. It is not SIP.

Sources and go deeper

  • RFC 3550 — last checked 2026-10

RTCP

RTP Control Protocol. Reports loss, jitter, and timing alongside RTP.

Sources and go deeper

  • RFC 3550 — last checked 2026-10

SRTP

Secure RTP. Encrypts and authenticates media packets.

Sources and go deeper

  • RFC 3711 — last checked 2026-10

SDES

Security Descriptions for SDP. Puts SRTP keying material in a=crypto.

Sources and go deeper

  • RFC 4568 — last checked 2026-10

DTLS-SRTP

Keying SRTP with a DTLS handshake instead of embedding keys in SDP.

Sources and go deeper

  • RFC 5764 — last checked 2026-10

SBC

Session border controller. A deployment role, usually a B2BUA, sitting on a trust boundary. Requirements are collected in RFC 5853.

Sources and go deeper

  • RFC 5853 — last checked 2026-10

B2BUA

Back-to-back user agent. A UAS on one side glued to a UAC on the other. Taxonomy: RFC 7092.

Sources and go deeper

  • RFC 7092 — last checked 2026-10

User agent

The SIP endpoint that originates or answers requests.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

UAC

User agent client. The side that sends a request.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

UAS

User agent server. The side that answers a request.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

Proxy

A SIP element that routes requests and responses without, by itself, being the session endpoint.

Sources and go deeper

  • RFC 3261 §16 — last checked 2026-10

Registrar

A server that accepts REGISTER and stores Contact bindings.

Sources and go deeper

  • RFC 3261 §10 — last checked 2026-10

Redirect server

A server that answers with 3xx and does not stay in the path.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

Transaction

One request and its responses, identified on a hop by the Via branch.

Sources and go deeper

  • RFC 3261 §17 — last checked 2026-10

Dialog

A peer relationship identified by Call-ID, local tag, and remote tag.

Sources and go deeper

  • RFC 3261 §12 — last checked 2026-10

Session

The media relationship negotiated with offer/answer. Distinct from the SIP dialog.

Sources and go deeper

  • RFC 3264 — last checked 2026-10

Call-ID

Header that stays constant for a dialog. Compact form: i.

Sources and go deeper

  • RFC 3261 §20 — last checked 2026-10

From tag

The tag parameter the UAC puts on From. It becomes part of the dialog ID.

Sources and go deeper

  • RFC 3261 §12 — last checked 2026-10

To tag

The tag the UAS adds to To. Absent on the initial request.

Sources and go deeper

  • RFC 3261 §12 — last checked 2026-10

CSeq

Command sequence: a number and a method token. The method must match the request.

Sources and go deeper

  • RFC 3261 §8 — last checked 2026-10

Via

The hop the response must return through. Compact form: v. The branch parameter identifies the transaction.

Sources and go deeper

  • RFC 3261 §8.1.1.7 — last checked 2026-10

Magic cookie

The branch prefix z9hG4bK required by RFC 3261 so proxies can tell old branches from new ones.

Sources and go deeper

  • RFC 3261 §8.1.1.7 — last checked 2026-10

Max-Forwards

Hop limit on a request. The recommended initial value is 70.

Sources and go deeper

  • RFC 3261 §8.1.1.6 — last checked 2026-10

Contact

Where this UA wants to be reached for this dialog. Compact form: m.

Sources and go deeper

  • RFC 3261 §20 — last checked 2026-10

Record-Route

A proxy’s request to stay on the path. The route set is built from these values.

Sources and go deeper

  • RFC 3261 §16 — last checked 2026-10

Route

The path a UA sends an in-dialog request along, learned from Record-Route.

Sources and go deeper

  • RFC 3261 §16 — last checked 2026-10

Request-URI

The URI on the request line. It is the current target, not always the original To URI.

Sources and go deeper

  • RFC 3261 §8 — last checked 2026-10

SIP URI

sip:user@host form defined by RFC 3261.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

SIPS URI

sip over TLS scheme. It is not itself an SRTP promise.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

tel URI

A telephone-number URI.

Sources and go deeper

  • RFC 3966 — last checked 2026-10

E.164

The ITU numbering plan. SIP carries those digits; it does not define the plan.

Sources and go deeper

  • RFC 3966 — last checked 2026-10

Early offer

An INVITE that already contains the SDP offer.

Sources and go deeper

  • RFC 3264 — last checked 2026-10

Delayed offer

An INVITE with no SDP. The offer arrives in a reliable response.

Sources and go deeper

  • RFC 3264 — last checked 2026-10

PRACK

Provisional acknowledgement. Makes selected 1xx responses reliable when 100rel is in use.

Sources and go deeper

  • RFC 3262 — last checked 2026-10

100rel

The option tag that turns on reliable provisional responses.

Sources and go deeper

  • RFC 3262 — last checked 2026-10

UPDATE

A method that can change session parameters, including before the initial INVITE finishes.

Sources and go deeper

  • RFC 3311 — last checked 2026-10

re-INVITE

A mid-dialog INVITE used to modify the session or refresh the target.

Sources and go deeper

  • RFC 6141 — last checked 2026-10

ACK

Acknowledges a final response to INVITE. The 2xx ACK is end to end; the non-2xx ACK is hop by hop.

Sources and go deeper

  • RFC 6026 — last checked 2026-10

BYE

Ends an established dialog.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

CANCEL

Gives up on an INVITE that has not received a final response.

Sources and go deeper

  • RFC 3261 — last checked 2026-10

OPTIONS

Asks a peer what it supports, and is widely reused as a keepalive.

Sources and go deeper

  • RFC 3261 §11 — last checked 2026-10

REGISTER

Creates or refreshes a binding between an address-of-record and a Contact.

Sources and go deeper

  • RFC 3261 §10 — last checked 2026-10

REFER

Asks another UA to issue a request, typically for transfer.

Sources and go deeper

  • RFC 3515 — last checked 2026-10

Replaces

  • RFC 3891 — last checked 2026-10

INFO

  • RFC 4733 — last checked 2026-10

  • RFC 3261 §22 — last checked 2026-10

GRUU

Globally Routable User Agent URI. A Contact that reaches one instance.

  • RFC 5627 — last checked 2026-10

Outbound

  • RFC 5626 — last checked 2026-10

Path

  • RFC 3327 — last checked 2026-10

Service-Route

Sources and go deeper

  • RFC 3608 — last checked 2026-10

Loose routing

A Route/Record-Route URI with the lr parameter. The request URI stays the target.

Sources and go deeper

  • RFC 3261 §16 — last checked 2026-10

rport

  • RFC 3581 — last checked 2026-10

  • RFC 8489 — last checked 2026-10

  • RFC 8445 — last checked 2026-10

SIP ALG
